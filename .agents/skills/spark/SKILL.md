# spark — 企画を面白くする

v1 の失敗は「設定はあるが面白さの仮説がない」企画を本文にしてしまうことだった。
spark の仕事は、本文を書く前に **面白さの仮説を言葉にする** ことである。
ここで沈黙した案は、本文にしても沈黙する。

## いつ使うか

- 新しい作品の立ち上げ時 (`python3 tools/init_work.py` で骨格を作った直後。
  出力先 (`proposals/` `work.md` `craft/engine.md`) は init_work.py が作るため、
  **必ず骨格生成の後に走らせる**)。
- 「何を書くか決まらない」「案が普通すぎる」と言われた時。
- 既存企画が退屈だと判明し、作り直す時。

本文を書き始めた後の作り直しは `change-set` 経由。spark は企画段階専用。

## 入力

- 作者のノリ (好きな作品・音楽・体験・言葉・写真)。
- ジャンル・媒体・長さ・制約・締切・NG。
- 参考作品 (「〇〇みたいな」)。**類似は差分を作る材料であり、模倣先ではない。**

足りない情報は一度に全部聞かない。最重要の1つ (誰の話にしたいか、または
何を読者に味わわせたいか) だけ確認して走る。残りは案を見せながら埋める。

## 手順

### 1. 素材を集める (5分)

作者のノリから **名詞を10個** 書き出す。感情語・抽象語は禁止 (具体物だけ)。
例: 傘 / 西口 / 名簿 / 雨 / 卵焼き / 定期券 / 屋上 / 消しゴム / 提灯 / 鍵。

この10個が、後の「固有の具体物」の在庫になる。ここが抽象語だけなら、
その企画はまだ具体を持っていない — 作者に具体物を1つ聞く。

### 2. 角度を5つに振り切る (5案の作り方)

同じ素材から、**別の問いを持つ5つの作品**を作る。角度は次の5軸で、
1案につき1軸を思い切り振る (少しずつ混ぜると5案が似て全滅する)。

| 案 | 振る軸 | 問いの形 | 例 (素材: 忘れ物預かり所) |
| --- | --- | --- | --- |
| 案1 | 誰の物語か | 視点を最も遠い人物に | 係員の物語 |
| 案2 | 何を失うか | 代償を最大化 | 忘れるたびに記憶を1つ失う |
| 案3 | 何が普通と違うか | 世界のルールを1つ変える | 忘れ物は翌日、別人の手に届く |
| 案4 | どんな具体物が残るか | 物から逆算 | 持ち手に文字が増える傘 |
| 案5 | どんな声で語るか | 語り口を主役に | 預かり所の名簿が一人称で語る |

### 3. 各案をまとめる (1案10分)

すべての案に、次の項目を書く。1つでも書けない案は捨てる。

1. **1行ログライン**: 「〇〇が、〇〇する話」。主人公+欲求+障害を1文に。
2. **面白さの源泉 (何で読者を引っ張るか)**: 構成の正しさだけでなく、この作品が
   読者を引っ張る核を自由に1行で (例: 絶望からの逆転 / 語り手の狂気 /
   掛け合いの可笑しさ / 不穏な謎 / 静かな余韻 / 生活の手触り)。
3. **冒頭3行**: 実際に書く (要約しない)。`docs/CRAFT.md` §2 の型5は強力な
   デフォルト。作風上あえて外す場合は狙いを1行添える。
4. **この作品にしかない具体物1つ**: 名詞で。題名にできる物が理想。
5. **類似作品との差分**: 「〇〇に似ているが、違うのは〇〇」の形で1文。
6. **危険 (つまらなくなる罠)**: この案が退屈になるとしたら、どうなる時か。

記入例:
```text
案4: 忘れ物預かり所
- ログライン: 傘を忘れた少女が、預かり所で「まだ忘れていない」と言われ、
  忘れるために雨へ戻る話。
- 面白さの源泉: 日常の隣にある不穏な謎と、少しずつ記憶が欠けていく切なさの落差。
- 冒頭3行: 「忘れ物預かり所は、駅の西口に、昨日からあった。窓口には
  名簿が一冊。少女の名前は、まだ載っていない。」
- 固有の具体物: 持ち手に知らない筆跡で文字が増える傘。
- 差分: 『xxx』に似ているが、違うのは「忘れることが目的になる」点。
- 危険: 説明で世界のルールを語り始めると、ただの奇妙な設定紹介になる。
```

### 4. 3つのゲートで捨てる (5案 → 2〜3案)

各案に次の3問をぶつける。**10秒沈黙したら捨てる。** 弁明は聞かない。

1. **一言で売る**: 「〇〇が〇〇する話」と言って、聞き手が「で、どうなるの?」
   と聞き返すか。説明を足さないと伝わらない案は弱い。
2. **読者が最初に知りたくなる問い**: 1文で書けるか。例「少女は、なぜ
   自分の傘を取り戻せないのか」。この問いが冒頭1ページで立つか。
3. **引っ張れるか**: その問いに答えるまで何話引けるか。3話未満なら短編向き
   (`mode: short`)。10話以上引くなら、問いを支える `engine` が必要。

捨て方の追加規則:
- 3問のどれか1つでも沈黙 → 捨てる。
- 差分が「〇〇っぽくない」の否定形しか言えない → 捨てる (既視感)。
- 具体物が名詞1つに絞れない → 捨てる (まだ世界が見えていない)。
- 主人公が最後まで誰かに連れて行かれるだけ → 捨てる (受動的)。
- 残った案同士が似ている → 弱い方だけ捨てる (2案で十分)。

### 5. 作者に選ばせる / 混ぜる

残った2〜3案を、**各項目のセットのまま** 作者に見せる。聞き方は1つだけ:
「どれを読みたいですか。理由は『どの場面が浮かぶか』で構いません。」

混ぜてよいのは「具体物 (案A) + 声 (案B) + 代償 (案C)」まで。
**世界のルールを2つ混ぜない** (破綻する)。混ぜた場合は3問ゲートを再実行する。

### 6. work.md と craft/engine.md を作る

選ばれた案から、次の2ファイルを作る。雛形は
`templates/craft-engine.md` と `templates/work.md` の「面白さの設計」節。

- `craft/engine.md`: 約束 / 面白さの源泉 / 欲求 / 欠落 / 恐怖 / 対立 / 代償 /
  時計 / ジャンルの快楽 / モチーフ / 禁じ手 / 意図的な逸脱 (任意)。**1項目1文で書く。**
- `work.md`: 面白さの設計 (約束・冒頭のフック・ジャンルの快楽・感情の弧・
  禁じ手・声・面白さの基準・モード)。
- あわせて `craft/voice.md` を起こす際は、「この作品であえて残す過剰さ・クセ・
  息抜き (削らない味)」を1〜2行書き、推敲で個性が均質化しない土台を作る。

engine の「約束」と「面白さの源泉」は、読者がこの作品から受け取る快楽と推進力
である。例: 「毎話、忘れ物が1つ増え、持ち主の記憶が1つ減る。読者は『次は何を
忘れるか』を楽しむ」。約束が1文で言えないなら、まだ spark は終わらない。

### 7. 記録

- `proposals/p-XXXX-spark.md` に5案とゲート結果を残す (捨てた案も残す —
  後の巻き返しの材料になる)。
- 採用理由を `dialogue.md` に1行。
- `work.md` の status は `setup` のまま (骨格生成時点の状態)。`active` 化は
  `init-work` の手順8で、spark と craft の記入が終わってから行う。

## アンチパターン

- **設定だけの案**: 世界観は語れるが「誰が何を欲しがるか」が言えない。
- **既視感のある案**: 差分が「〇〇のパロディ」だけ。差分は問いの違いで作る。
- **受動的な主人公**: 事件に巻き込まれるだけで、何も選ばない。
- **テーマはあるが事件がない案**: 「〇〇とは何か」を語りたいだけの案。
- **5案が全部同じ**: 角度を少しずつ混ぜた結果。1軸ずつ振り切ること。
- **案を10個出す**: 作者が選べない。5案→2〜3案に絞ってから見せる。
- **作者に「どれがいいですか」とだけ聞く**: 選ぶ基準 (どの場面が浮かぶか)
  を添える。
- **ゲートを通さず本文へ**: 3問に答えられない案は、書いても退屈になる。
  本文を書くのは `write-scene` の仕事で、spark はその前の関門である。

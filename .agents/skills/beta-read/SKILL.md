# beta-read — 初読者視点の通読

critic 検査は正典・契約・計画を全部知った上で読む。だから
「知っているから分かる」落とし穴を通す。初読の読者が読んで
分かるか・面白いかは別の検査として必要。

## 読み方 (重要)

- **正典メモ・契約・計画の内容を読者知識として使わない。**
  読者が持つ知識は「本文が明示的に与えたもの」だけ。
- 読者が知っていることと作中人物が知っていることの差を意識する
  (作者視点で「当然」としている情報が本文にないことを検出する)。
- `[秘密]` 正典は伏線効果の判断材料 — 「回収される予定の秘密」が
  早漏気味なら指摘する。

## 手順

1. 対象範囲を決める (指定シーン / 話単位 / 生成済み全部)。
2. `plan/tree.md` の順序で `scenes/` を通読する。
3. 以下の観点で findings を集める:
   - **混乱**: 誰がどこにいるか追えない・時系列が掴めない・
     唐突に見える転換
   - **前提知識不足**: 本文に出ていない情報を前提にした記述
   - **説明しすぎ**: 読者が既に知ることを繰り返す説明口調
   - **テンポ**: 停滞・駆け足すぎ・山場の位置
   - **感情線**: 人物の行動動機が読者から見て自然か
   - **引き**: シーン・話の切りが次を読ませるか
4. `reviews/beta-<対象範囲>-<date>.md` に `templates/review.md`
   の形式で記録。severity は「初読者がつまずく度合い」で付ける。
5. 修正が要る箇所は `changeset` または新規 `writing_contract` 提案として
   起票し、作者に提示する。

## 注意

- 「自分ならこう書く」趣味の指摘と、客観的に読者が混乱する点を
  分けて書く。severity=low に止めるべきものを high にしない。
- 意図的な難解さ・情報統制が作風として指定されている場合は
  `work.md` の検査ポリシーに従う。
- 通読で「正典との矛盾」を見つけても、それは beta-read の管轄外 —
  `.agents/skills/review-change` の決定的検査で扱う。

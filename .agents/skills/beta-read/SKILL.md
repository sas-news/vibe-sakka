# beta-read — 初読者視点の通読

**批評は必ず新規コンテキストで行う。** 書いた本人・正典と計画を知った
状態の自分が読んでも「分かる人が分かるか」の確認にしかならず、
「ここは後で回収する」前提知識で我慢して読む・構造反復を「設計どおり」
と正当化してしまう。

## 外部化のしかた

- **サブエージェント・別セッションが使えるハーネス**: `export` した
  原稿だけを渡し、`canon/` `plan/` `entities.md` を一切読ませない。
  「読者と同じ無知」を強制する。
- **使えないハーネス**: 正典・計画・登場要素を開かず、本文のみを
  読み直して代替。ただしこの代替での検査は lint・秘密・ID 参照の
  決定的項目に限定し、**面白さの評価は必ず外部化する**。

## 読者として読む

- 読者が持つ知識は「本文が明示的に与えたもの」だけ。正典メモ・契約・
  計画の内容を読者知識として使わない。
- `[秘密]` 正典は伏線効果の判断材料 — 「回収される予定の秘密」が
  早漏気味なら指摘する。
- 「自分ならこう書く」趣味の指摘と、客観的に読者がつまずく点は分ける。

## severity の較正 — 「読者離脱度」

- **high**: 実読者がこの本を閉じるレベル (分からない・退屈・裏切られた)
- **medium**: 読み飛ばす・流すレベル
- **low**: 些細な違和
- **info**: 参考情報

「書いた側には分かる」では severity を下げない。

## 手順

1. 対象範囲を決める (指定シーン / 話単位 / 生成済み全部)。
2. `export` で対象範囲の原稿を出す。
3. 外部化した通読で findings を集める (観点: 混乱 / 前提知識不足 /
   説明しすぎ / テンポ / 感情線 / 引き / 構造反復 / 用語負荷)。
4. `reviews/beta-<対象>-<date>.md` に `templates/beta-review.md` の
   形式で記録。
5. **閾値判定**: findings が high 1件以上 or medium 3件以上
   (`work.md` で変更可) なら、write-scene の revise を自動発火し、
   auto 自律運転中なら継続を停止して作者に報告する。
6. 修正が要る箇所は `changeset` または新規 `writing_contract` 提案として
   起票し、作者に提示する。

## 注意

- 「正典との矛盾」は管轄外 — `.agents/skills/review-change` で扱う。
- 意図的な難解さが作風として指定されている場合は `work.md` の
  検査ポリシーに従う。

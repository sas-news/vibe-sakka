# polish — 全原稿の推敲

polish は「誤字を直す」工程でも、「一律に字数を削り込む」工程でもない。
**AI特有のノイズ (冗長な言い換え・説明過多・重複) を容赦なく削りつつ、
`craft/voice.md` に定めた作品の温度・リズム・意図的な過剰さを守り、境界を強くする**
工程である。全原稿に対して最低1回通す。

## いつ使うか

- 全話 (または公開単位) の本文が書き終わった後、`release-gate` の前。
- `beta-read` の修正 (`revise`) が済んだ後、公開前の最終仕上げ。
- 短編でも省略しない。1シーンだけの作品でも、通読→ノイズ削減→具体化→記録を行う。

## 入力

- 対象原稿 (`out/<title>.md`、または `scenes/*.md` を連結したもの)。
- `reviews/beta-*.md` の findings (退屈・予定調和・初見の理解不足の指摘)。
- `work.md` の面白さの設計・禁じ手、`craft/engine.md` (意図的な逸脱)、
  `craft/voice.md` (声と**削らない味**)。
- `templates/polish-report.md` (記録用紙)。

## 手順

### 1. 通読して退屈箇所・引っかかりを記録する

原稿を一度、**読者として** 最初から最後まで読む。作者・編集者の目で読まない。
退屈した・読み飛ばした・意味が分からなかった箇所に、行番号と引用を付けて
メモする (この時点では直さない)。

記録の形: `L42 引用「〜」— 理由: 説明が続く / 感情が見えない / 既に知っている`
- 目安: 1万字あたり5〜15箇所。0箇所なら、読者が自分に遠慮している。

### 2. ノイズだけを削り、作品の味を残す

**優先順位**: **AI特有の冗長な言い換え・説明過多・重複は容赦なく削るが、
`craft/voice.md` に定めた作品の温度・リズム・意図的な過剰さ (削らない味) と、
完全初見の読者を置いてけぼりにしない最小限の補助線は守る。**

削減率 (10–20% 等) を機械的な目標にしない。一律に削ろうとすると、生活感・
ユーモア・感情の揺れ・世界観の最小限の補助線まで削ぎ落ち、淡々とした舞台劇に
均質化しやすい。ノイズが少ない原稿は無理に削らなくてよい。

容赦なく削るノイズの候補:
1. まとめ・総括・教訓の段落 (CRAFT §8 症状9/15)。
2. 説明過多・AI特有の冗長な言い換え (状態・関係・性格のくどい要約) — 動作に
   置換できるものは置換、不要なものは削除 (§7)。
3. 目的も味もない移動・挨拶・食事・片付けの手順。
4. 重複 (同じ情報の2回目以降)。
5. 効果のない薄い副詞 (とても/すごく/本当に/なんとなく/少し)。
6. 比喩の2つ目以降 (1文に1つが目安)。

**削る判断基準 (4問)** — すべて「いいえ」なら削る:
1. これを削ると、初見読者の状況・仕組み・因果の理解が損なわれるか。
2. これを削ると、人物の印象・温度・生活感が痩せるか。
3. これを削ると、後の感情・伏線・リズムが弱くなるか。
4. `craft/voice.md` の「削らない味」(過剰さ・クセ・息抜き) に該当するか。

**削ってはいけない**: turn / cost / button / detonator / hook / pull、
具体物の初出、伏線の設置、`craft/voice.md` に宣言された「削らない味」、
初見読者が世界のルールに付いていくための最小限の補助線。
削った結果 200字未満になった場面は統合を検討する (lint L012)。

### 3. 具体化する

意図なく浮いている抽象語・感情語・説明を、事物と動作に置換する (CRAFT §6 の変換表20例)。
- 点検する語: 悲しい/嬉しい/怖い/寂しい/美しい/すごい/とても/気持ち/
  感じ/ということ/もの。
  (ただし `craft/voice.md` の「削らない味」で語り手の過剰な心情吐露や
  一人称独白を売りにする場合は、狙いどおりに効いている箇所を潰さない。)
- 1場面につき具体物を最低3つ。うち1つをモチーフ (繰り返す物) にする。
- 五感を2つ以上入れる (視覚だけにしない)。

### 4. 声を揃える

台詞だけを抜き出して並べ、**誰が言ったか判別できるか** 確認する。
- 人物ごとに「使う語彙1つ」「言わない語彙1つ」「文の長さの癖」を
  `craft/voice.md` と照合する。
- 地の文の語り口 (人称・距離・時制・テンポ) と「削らない味」を `craft/voice.md` に合わせる。
- 全員が同じ丁寧さ・同じキメ台詞調なら、温度や生活感の差を戻す (CRAFT §5)。

### 5. リズムを整える

- 長短を混ぜる。単調なリズムを崩す (`craft/voice.md` のリズム方針に合わせる)。
- 読みにくい長文 (120字超) を割る。長段落 (600字超) を分ける (lint W004。
  実験文体等で意図的な長文を宣言している場合は除く)。
- **読み上げる**: 声に出して詰まる箇所・息が続かない箇所を直す。
  声に出せない環境では、句点で息継ぎをしながら黙読し、詰まる文を印す。
- 同じ文末 (〜た。〜た。〜た。) が意図なく3回続いたら1つ変える。

### 6. 章頭と章末を強化する

- 章頭: 最初の3行で問いが立つか (CRAFT §2 の型5)。説明・情景から始まって
  いたら書き直す (`craft/engine.md` に意図的な導入の狙いがある場合を除く)。
- 章末: 引きの3条件 (未解決・具体・次に読む理由) を満たすか (§3 の型5)。
  総括・教訓で終わっていたら、新情報か選択を残して切る (静かな余韻を宣言して
  いる場合は、説明ではなく余韻の像で切れているか確認する)。
- 全話について「hook / pull (または宣言した意図的逸脱)」を1話ずつ確認する
  (`templates/release-checklist.md` の該当欄)。

### 7. アーティファクトを掃除する

決定論で捕まえられるものは道具に任せる。

```bash
# 安全な自動修正 (BOM/CRLF・行末空白・空行過多・区切り統一・(了) 重複)
# 対象は正本の scenes/*.md。out/ は export で再生成される派生物なので fix しない
python3 tools/manuscript_lint.py --fix scenes/*.md

# E 0 件になるまで確認 (本文の語句は --fix では変わらない)
python3 tools/manuscript_lint.py --workdir . out/*.md
```

`--fix` が直さないもの (E L003 ビート見出し / E L004 重複 / E L011 シーンID /
E L002 台帳ID / E L001 URL) は手で直す。直せない場合は `release-gate` に
進まず、作者に報告する。W (警告) は推敲対象として点検し、`craft/voice.md` の
味として意図的に残すものは理由を推敲記録に書く。

### 8. 記録し、推敲済みフラグを立てる

1. `templates/polish-report.md` で `reviews/polish-<YYYYMMDD>.md` を作る。最低限:
   - before / after の字数と増減率 (実測の記録。削減率のノルマはない)。
   - 削ったノイズ (種類と件数)、具体化したもの、声・リズムの主な修正。
   - **守った味** (`craft/voice.md` の狙いに照らして残したもの)・迷ったもの。
   - lint の最終結果 (E 0 / W 件数)。
2. 対象の各 `scenes/<E-S>.md` のヘッダを `polished: true`、
   `polish_review: reviews/polish-<YYYYMMDD>.md` に更新する (rev は本文を
   書き換えた場合のみ +1。フラグ更新だけなら rev は据え置きでよい)。
3. `python3 tools/manuscript_lint.py --workdir . out/*.md` が E 0 であること、
   `python3 tools/release_gate.py --workdir .` が合格することを確認する。

記録のない原稿、`polished: true` の無いシーンが1つでもある原稿は
`release-gate` で落ちる。

## 削る before/after 実例3つ

**例1 説明の削除 (要約→動作)**
- before (112字): 「ミナはとても驚いた。まさか自分の傘がまだ預かっていない
  とは思っていなかった。係員の態度も、どこか意味深で、彼女は不安になった。」
- after (54字): 「ミナは名簿を見た。自分の名前の欄だけ、まだ空だった。
  係員は、名簿を閉じた。」
- 変更: 感情の名指し3つと推測を削り、名簿という具体物に置換。削除率52%。

**例2 重複の削除 (同じ情報の2回目)**
- before: 「雨はまだ降っていた。彼女は傘を持っていなかった。雨の中を、
  彼女は走った。濡れながら、彼女は走った。」
- after: 「雨の中を、彼女は走った。」
- 変更: 既出情報 (雨・傘なし・走る) の反復を1文に。削除率78%。
  ただし turn/cost に関わる反復は残す (ここでは cost が「濡れる」なので
  「雨の中を」だけは残した)。

**例3 章末の引きの強化 (総括→新情報)**
- before: 「こうしてミナは、忘れ物預かり所の不思議さを知ったのだった。
  明日もまた、彼女はそこへ行くだろう。」
- after: 「係員は名簿をめくり、次の頁を開いた。そこには、ミナの名前と、
  まだ書かれていない日付があった。」
- 変更: 総括2文を削り、新情報 (まだ書かれていない日付) 1つで切る。
  引きの3条件を満たす。削除ではなく置換だが、字数はほぼ同じ。

## 出力・記録先

| 出力 | パス |
| --- | --- |
| 推敲記録 (必須) | `reviews/polish-<YYYYMMDD>.md` |
| 修正済み原稿 | `scenes/<E-S>.md` (rev+1) → `out/` は export で再生成 |
| 推敲済みフラグ (必須) | 各 `scenes/<E-S>.md` ヘッダの `polished: true` と `polish_review: reviews/polish-<YYYYMMDD>.md` |
| 声の更新 (必要なら) | `craft/voice.md` |

## アンチパターン

- **誤字直しだけで終わる**: 誤字・表記ゆれはここで直すが、polish の主眼はノイズ削減と具体・声の磨き上げ。lint はアーティファクトの検査であって推敲の代わりではない。
- **削減率ノルマで味まで削る**: 10–20% 削るために生活感・ユーモア・感情の揺れ・初見向けの補助線まで刈り込み、淡々とした原稿にしてしまう。
- **ノイズを「味」と言い張って全部残す**: AI特有の冗長な言い換え・説明過多・既知の反復は容赦なく削る。
- **削るだけで具体化しない**: 短くなったが退屈なまま。§3 を必ず通す。
- **声を全部同じにする**: 揃えるのは語り口であって、人物の個性ではない。
- **意味を変える**: 推敲は内容を変えない。内容変更は `change-set`。
- **推敲中に新しい場面を書く**: 新規執筆は `write-scene`。polish は既存原稿のみ。
- **字数合わせで水増し**: 膨張パスは禁止 (AGENTS.md 品質停車点)。
- **記録なし**: `reviews/polish-*.md` がない原稿は公開できない。

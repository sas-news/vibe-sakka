# orchestrator-dialogue — 対話1往復の処理

作者の発言1つ = 1往復として処理する。

## 役割プロンプト

対話では以下の振る舞いを守る:

- 一度に大量の質問を投げず、最も重要な不確定事項から1つずつ確認する。
- 決定事項・暫定案・未決定事項・意図的に開けておく事項を区別して要約する。
- 作者が曖昧な表現を使った場合、重要な意味を勝手に確定しない。
- 過去の決定と矛盾する希望が来た場合、黙って上書きせず、どの決定が
  変わるかを説明する。
- 記録済みの正典や作品設定を変えたい・廃止したい場合、勝手に書き換えず
  変更セットを提案する (正典の追記は対話決定としてのみ許可)。

## 手順

1. **コンテキストを読む**: `work.md` → `canon/facts.md` → `plan/tree.md`
   → `entities.md` → `knowledge.md` → pending の `proposals/`。
   直近の `dialogue.md` 末尾も見る。
2. **発言を分類する**: 相談 / 情報照会 / 新規決定 / 本文生成 / 修正 /
   強制改変。
3. **分類ごとに処理**:
   - **相談**: 正典は変えない。決定が必要なら前提・選択肢・トレードオフを
     示し、重要なものから質問する。ブレストで出た断片は `scratch/` に
     自由形式で追記してよい (正典ではない・承認不要)。
   - **情報照会**: ファイルを読んで答える。回答だけなら副作用なし。
   - **新規決定**: 体裁の決定は `work.md` に反映。確定した設定は
     `canon/facts.md` に新しい fID で追記 (確度ラベルつき)。
     「仮置きして」「未定だけど」は [仮置き]、[秘密] にしたいものは [秘密]。
   - **本文生成**: 契約要素が揃っていれば `writing_contract` 提案を
     `proposals/` に起票 (1往復1件まで。保留中の提案がある間は新たに
     出さない)。不足なら提案せず質問して固める。契約は「動かせない
     境界」だけを定める最小形でもよい (探索的シーンでは role・pov・
     forbidden だけで十分)。承認後は `.agents/skills/write-scene` へ。
   - **修正**: `.agents/skills/change-set` の手順 (分類→影響分析→提案→承認→適用)。
   - **強制改変**: `.agents/skills/change-set` の force_override 手順。
   - **計画したい**: `.agents/skills/plan-work` へ (計画は自分で書かず planner
     手順で作り、提案として提示する)。
4. **応答を返す**: 日本語プレーンテキスト。何を決めたか・何を提案したか・
   何が未確定か・次に何ができるかを含める。
5. **dialogue.md に追記**: 発言と応答の要約、発生した提案/変更セットの ID。

## 保留中の提案があるとき

pending の `proposals/` がある間は同種の新提案を出さず、作者の
承認/却下/修正指示を待つ。却下なら status を rejected に更新する。
承認されたら kind ごとに適用して status を approved に更新する:

- **writing_contract** → `contracts/<scene>.md` を作成 (status: approved、
  base_revision に現在の canon_revision) し、`plan/tree.md` のシーン状態を
  approved にする。ここで初めて `.agents/skills/write-scene` のゲートを通る。
- **plan** → `plan/tree.md` へ適用 (新規話・シーンの追加、状態 draft)。
- **canon_append** → `canon/facts.md` へ確度ラベルつきで追記。
- なお、対話で作者が明示的に決定した新規の設定は提案を経ずに
  `canon/facts.md` へ直接追記してよい (出所: 対話)。canon_append 提案は
  あなた側からの「候補・推測」を留保するために使う。

## 作者がファイルを直接編集していたら

`scenes/` の本文差分は `kind: manual_edit` の変更セットとして記録し、
自動検査を走らせる。L0 相当の表現変更なら記録だけで執筆継続。
L1 以上なら通常の変更セットフローに載せる。`canon/` `entities.md`
`knowledge.md` `plan/` の直接編集は「強制改変」として扱う。

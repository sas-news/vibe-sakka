# scene-craft — 場面の設計

場面は「誰が・何を欲しがり・何に阻まれ・何が変わり・何を払うか」の単位である。
この設計を飛ばすと、整っていても要約体になりやすい。
**本文の前に、場面を1文で説明できる状態にする。**

## いつ使うか

- `plan-work` の後、`write-scene` の前。契約の craft 欄を埋める時。
- `beta-read` が退屈を指摘し、場面から作り直す時。
- 「何を書けばいいか分からない」時 — それは設計が足りないサイン。

## 入力

- `plan/tree.md` の当該話: hook / promise / detonator / payoff。
- `work.md` の面白さの設計、`craft/engine.md`、`craft/voice.md`。
- 直前シーンの exit、次シーンの entry、作者の制約 (下限字数・禁止事項)。

## 手順

`templates/writing-contract.md` の craft 欄を上から埋める。
※以下の例 (傘・名簿など) は一例。例に引っ張られず、作品の具体物で考える。各欄は短く (1文が目安)。
書けない欄は空欄のまま残してよい。本文を書きながら見えてくることもある。
作者の決定が必要な欄だけ、1つずつ聞く。

### 1. scene_job — 機能
物語に対する役割を1文で。出来事の説明ではなく機能を書く。
- ○ 「少女が、忘れることを初めて自分で選ぶ場面」
- × 「少女が預かり所に行く場面」(機能がない)

### 2. dramatic_question — 場面の問い
読者が答えを知りたくなる疑問文を**1つだけ**。場面内で答える。
- ○ 「少女は、傘を忘れられるのか」
- × 「少女の過去は何か、係員は何者か」(問いが多すぎる)

### 3. want — 欲求
「誰が・何を・今すぐ」を動詞で。抽象語 (幸せ・成長) は動作になりにくい。
- ○ 「ミナが、自分の傘を今すぐ取り戻したい」
- × 「ミナが、自分を見つめ直したい」(行動にならない)

### 4. obstacle — 障害
障害は、拒む意思を持つ人物か、動かない物のほうが緊張を作りやすい。
- ○ 「係員が『まだ預かっていない』と受け取りを拒む」
- × 「雨が降っている」(背景。ノーと言う主体がいない)

### 5. turn — 転
「予想 → 実際」の形で。読者と主人公の予想がどちらも裏切られるのが理想。
- ○ 「傘を受け取ると思ったら、忘れてから来いと言われる」
- × 「特に何も起きない」(turn のない場面は skip test に落ちる)

### 6. cost — 代償
turn の結果、失う/差し出すもの。無料の解決は書かない。
- ○ 「傘を持ったまま雨へ戻る (濡れる・遅刻する)」
- × 「特に何も失わない」(読者の投資が回収されない)

### 7. entry — 入り (遅く入る)
最初の1文を実際に書く。挨拶・移動・状況説明から始めない。
- ○ 「『お預かりは、まだです』」(台詞から)
- × 「ミナは駅に着き、改札を出て、西口へ向かった」(移動から)

### 8. exit — 出 (早く出る)
最後の1文を書く。後片付け・総括・教訓を書かない。
- ○ 「ミナは、傘を持ったまま、改札を戻った。」
- × 「こうしてミナは、自分が忘れっぽいことに気づいたのだった。」

### 9. button — 場面を閉じる像
読者に残す像。exit と別でもよい (動作の終わり + 余韻の像)。
余韻の一行に限らない。ぶつ切れ、不快な一言、説明しない動作、コミカルな
オチも button になりうる。作品のトーンに合う形を選ぶ。
- ○ 「手元の傘が、少しだけ重い。」
- × 「彼女はとても不思議な気持ちになった。」(感情の名指し)

### 10. detonator — 爆点
DESIGN §4 の detonator を場面に1つ。「予想→裏切り→伏線」の3点で。
- ○ 「予想: 傘を受け取る / 裏切り: まだ預かっていない / 伏線: 名簿に名前が先にある」
- × 「裏切り: 実は宇宙人 / 伏線: なし」(納得のない裏切りはご都合)

### 11. concrete_details — 具体物3つ
名詞で3つ。「素材+傷/色/音」を付ける。形容詞は不可。1つをモチーフにする。
- ○ 「持ち手の焦げた傘 / 名簿の赤い罫線 / 窓口の鈴の音」
- × 「美しい傘 / 古い名簿 / 静かな音」

### 12. subtext — 言わないこと
台詞の表面と、言わない本音を1組で。
- ○ 表面「その傘、返さなくていいんですか」/ 本音「返してほしくない」
- × 表面「私はあなたが好きです」/ 本音なし (言ってしまっている)

### 13. pov_filter — 視点の濾過
視点人物が知覚できないもの・知らないことを書かない。
- ○ 視点ミナ: 「男の手が、名簿の上で止まった」(見える)
- × 視点ミナ: 「男は心の中で、彼女を哀れんでいた」(知覚不能)

### 14. skip_test — 削るかの判定
「飛ばしたら後の話が壊れるか」。壊れる理由を1文で。言えなければ削る/統合。
- ○ 「飛ばすと、持ち手の文字の意味が分からなくなる」
- × 「飛ばしても分かるが、雰囲気が欲しい」(雰囲気は理由にならない)

### 15. prose_floor と prohibit_summary
`prose_floor` は下限字数の目安。目標ではない。水増しはしない。200字未満は統合を検討 (lint L012)。
`prohibit_summary` は既定 true。要約体を望む作品では契約で false にする。

### 16. 1文要約テスト
場面を1文に要約し、「意外」か「代償」があるか確認する。
- ○ 「傘を取りに行った少女は、まだ忘れていないと言われ、忘れるために雨へ戻る。」
- × 「少女は駅で傘を受け取った。」(意外も代償もない → 設計をやり直す)

### 17. 要約体セルフ検査 (目安)
複数当てはまるなら、場面として弱いかもしれない。
- [ ] 「〜することになる」「〜のである」「〜だろう」で進む。
- [ ] `一` `二` `【…】` の見出しで区切られている。
- [ ] 出来事が「そして」「その後」で飛ばされ、間が演じられていない。
- [ ] 感情が名指しされている (悲しい/嬉しい/怖い)。
- [ ] 台詞が説明だけを運ぶ (二人が既知のことを確認し合う)。
- [ ] 五感の具体物が1つもない。
- [ ] 主人公が何も選ばず、誰かに連れて行かれるだけ。
- [ ] 1文要約に意外も代償もない。

**3分口頭テスト**: 場面を口で説明するとき、動作を真似できるか。「傘を持つ」
「名簿を閉じる」が再現できるなら場面。「複雑な気持ちになった」だけなら、
要約に寄っているかもしれない。

### 18. 契約を approved にする
書き始める目安は `scene_job` / `want` / `turn` の3つ。これが決まっていれば
approved にしてよい。他の欄は書く前でも書きながらでもよく、空欄は未決定として
残す (write-scene も同じ3項目を見る)。埋めた craft 欄を
`contracts/<E-S>.md` に記入し `status: approved` にする。`plan/tree.md` の
シーン状態も approved に。

## 記入例

```yaml
scene_job: 少女が、忘れることを初めて自分で選ぶ場面
dramatic_question: ミナは傘を忘れられるのか
want: ミナが自分の傘を今すぐ取り戻したい
obstacle: 係員が「まだ預かっていない」と受け取りを拒む
turn: 傘を受け取ると思ったら、忘れてから来いと言われる
cost: 傘を持ったまま雨へ戻る (濡れる・遅刻する)
entry: 「お預かりは、まだです」
exit: ミナは、傘を持ったまま、改札を戻った。
button: 手元の傘が、少しだけ重い。
detonator: 名簿に、まだ忘れていないミナの名前が先に書いてある
concrete_details: 持ち手の焦げた傘 / 名簿の赤い罫線 / 窓口の鈴の音
subtext: 表面「その傘、返さなくていいんですか」/ 本音「返してほしくない」
skip_test: 飛ばすと、持ち手の文字の意味が分からなくなる
prose_floor: 800
prohibit_summary: true
```

## 出力・記録先

| 出力 | パス |
| --- | --- |
| craft 欄入り契約 | `contracts/<E-S>.md` |
| 計画状態の更新 | `plan/tree.md` |
| 設計の相談メモ (任意) | `proposals/p-XXXX.md` |

## アンチパターン

- **契約が本文のあらすじになる**: craft 欄は機能・問い・変化だけを書く。
- **want が抽象語**: 「成長したい」は動作にならない。
- **obstacle が天候・雰囲気**: ノーと言う主体がいない障害は緊張を作らない。
- **turn がない / cost がない**: 何も変わらず、ただで解決する。削るか作り直す。
- **entry が説明・exit が総括**: 遅く入り、早く出る (CRAFT §1原則9)。
- **concrete_details が形容詞**: 「美しい」「古い」は具体物ではない。
- **subtext なし**: 全員が本音を言い、台詞が説明になる。
- **場面を2つ混ぜる**: turn が2つある契約は2場面に分ける。
- **全欄を埋めようとする**: 探索的な場面は欄を開けてよい。scene_job / want /
  turn だけ決めておくと書きやすい。

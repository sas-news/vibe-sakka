# scene-craft — 場面の設計

場面は「誰が・何を欲しがり・何に阻まれ・何が変わり・何を払うか」を基本の型とする。
この設計を飛ばして書いた本文は、整っていても要約体になりやすい。
**本文の前に、場面を1文で説明できる状態にする。**

> 以下の craft 欄は**迷ったときの強力なデフォルト**である。静かな余韻・日常の
> 呼吸・コメディの脱力・実験構成などで意図的に外す場合は、`craft/engine.md` や
> `craft/voice.md` に狙いを宣言したうえで、該当欄にその狙いを書く。

## いつ使うか

- `plan-work` の後、`write-scene` の前。契約の craft 欄を埋める時。
- `beta-read` が退屈・予定調和 (お使い) を指摘し、場面から作り直す時。
- 「何を書けばいいか分からない」時 — それは設計が足りないサイン。

## 入力

- `plan/tree.md` の当該話: hook / promise / detonator / payoff。
- `work.md` の面白さの設計、`craft/engine.md`、`craft/voice.md`。
- 直前シーンの exit、次シーンの entry、作者の制約 (下限字数・禁止事項)。

## 手順

`templates/writing-contract.md` の craft 欄を上から埋める。**各欄は1文。**
書けない欄は空欄にせず、作者に1つだけ聞く。

### 1. scene_job — 機能
物語に対する役割を1文で。出来事の説明ではなく機能を書く。
- ○ 「少女が、忘れることを初めて自分で選ぶ場面」
- × 「少女が預かり所に行く場面」(機能がない)

### 2. dramatic_question — 場面の問い
読者が答えを知りたくなる疑問文を**1つだけ**。場面内で答える。
- ○ 「少女は、傘を忘れられるのか」
- × 「少女の過去は何か、係員は何者か」(問いが多すぎる)

### 3. want — 欲求
「誰が・何を・今すぐ」を動詞で。抽象語 (幸せ・成長) は不可。
- ○ 「ミナが、自分の傘を今すぐ取り戻したい」
- × 「ミナが、自分を見つめ直したい」(行動にならない)

### 4. obstacle — 障害
「ノーと言えるもの」= 拒否する意思を持つ人物か、動かない物。
- ○ 「係員が『まだ預かっていない』と受け取りを拒む」
- × 「雨が降っている」(背景。ノーと言う主体がいない)

### 5. turn — 転
「予想 → 実際」の形で。読者と主人公の予想がどちらも裏切られるのが理想。
- ○ 「傘を受け取ると思ったら、忘れてから来いと言われる」
- × 「特に何も起きない」(turn のない場面は skip test に落ちる)

### 6. cost — 代償
turn の結果、失う/差し出すもの。無料の解決は書かない。
- ○ 「傘を持ったまま雨へ戻る (濡れる・遅刻する)」
- × 「特に何も失わない」(読者の投資が回収されない)

### 7. entry — 入り (遅く入る)
最初の1文を実際に書く。挨拶・移動・状況説明から始めない。
- ○ 「『お預かりは、まだです』」(台詞から)
- × 「ミナは駅に着き、改札を出て、西口へ向かった」(移動から)

### 8. exit — 出 (早く出る)
最後の1文を書く。後片付け・総括・教訓を書かない。
- ○ 「ミナは、傘を持ったまま、改札を戻った。」
- × 「こうしてミナは、自分が忘れっぽいことに気づいたのだった。」

### 9. button — 場面を閉じる一行
読者に残す最後の一撃。静かな余韻に限らず、ぶつ切れ・不快・コミカル・言い放し等、
作品のトーンに合わせて選ぶ (exit と別でもよい)。
- ○ 「手元の傘が、少しだけ重い。」
- × 「彼女はとても不思議な気持ちになった。」(説明で締める)

### 10. detonator — 爆点
DESIGN §4 の detonator を場面に1つ。「予想→裏切り→伏線」の3点で。
- ○ 「予想: 傘を受け取る / 裏切り: まだ預かっていない / 伏線: 名簿に名前が先にある」
- × 「裏切り: 実は宇宙人 / 伏線: なし」(納得のない裏切りはご都合)

### 11. concrete_details — 具体物3つ
名詞で3つ。「素材+傷/色/音」を付ける。形容詞は不可。1つをモチーフにする。
- ○ 「持ち手の焦げた傘 / 名簿の赤い罫線 / 窓口の鈴の音」
- × 「美しい傘 / 古い名簿 / 静かな音」

### 12. subtext — 言わないこと
台詞の表面と、言わない本音を1組で。
- ○ 表面「その傘、返さなくていいんですか」/ 本音「返してほしくない」
- × 表面「私はあなたが好きです」/ 本音なし (言ってしまっている)

### 13. pov_filter — 視点の濾過
視点人物が知覚できないもの・知らないことを書かない。
- ○ 視点ミナ: 「男の手が、名簿の上で止まった」(見える)
- × 視点ミナ: 「男は心の中で、彼女を哀れんでいた」(知覚不能)

### 14. skip_test — 削るかの判定
「飛ばしたら後の話が壊れるか」。壊れる理由を1文で。言えなければ削る/統合。
- ○ 「飛ばすと、持ち手の文字の意味が分からなくなる」
- × 「飛ばしても分かるが、雰囲気が欲しい」(雰囲気は理由にならない)

### 15. prose_floor と prohibit_summary
`prose_floor` は下限字数。**目標ではない。水増し禁止。** 200字未満は統合を検討 (lint L012)。
`prohibit_summary: true` 固定。ビート見出し・「〜することになる」の要約・箇条書きを書かない。

### 16. 1文要約テスト
場面を1文に要約し、「意外」と「代償」が両方あるか確認する (静かな余韻・日常系
などで外す場合は、`craft/engine.md` に宣言した狙いと噛み合っているか確認する)。
- ○ 「傘を取りに行った少女は、まだ忘れていないと言われ、忘れるために雨へ戻る。」
- × 「少女は駅で傘を受け取った。」(意外も代償もない → 設計をやり直す)

### 16.5 展開が淡々・お使いになりそうなときの打開策 (オプション)
構成は綺麗なのに予定調和・お使い進行・淡々とした舞台劇になりそうなときは、
`docs/CRAFT.md` §4「展開が淡々としたときの打開策カタログ」から作品タイプに合う
引き出しを**1つだけ任意に**選んでよい (必須要件ではない):
- **失敗と悪化 (`No, and furthermore`)**: 最初の作戦が空振りして状況がこじれる。
- **予定外の割り込み**: 段取り通りに進む瞬間に第三者や時間切れが割り込む。
- **主人公の判断ミス・取り乱し**: クールすぎる主人公に焦りや不格好な選択を挟む。
- **敵役・障害側なりの筋の通った正義**: 相手側の譲れない理屈や生活を1つ見せる。
- **日常のズレ・息抜きからの急転**: 生活感や可笑しさの直後に異物を落として温度差を作る。
- **身体で分かる小さな実験**: 独自設定やメタファーを講義せず、小さな実演や誤用で共有する。

### 17. 要約体セルフ検査 (書く前と後に必ず)
1つでも当てはまったら、その場面は要約体である。
- [ ] 「〜することになる」「〜のである」「〜だろう」で進む。
- [ ] `一` `二` `【…】` の見出しで区切られている。
- [ ] 出来事が「そして」「その後」で飛ばされ、間が演じられていない。
- [ ] 感情が安易に名指しされている (`craft/voice.md` の「削らない味」で意図的な
      心情吐露を宣言している場合は除く)。
- [ ] 台詞が説明だけを運ぶ (二人が既知のことを確認し合う)。
- [ ] 五感の具体物が1つもない。
- [ ] 主人公が何も選ばず、誰かに連れて行かれるだけ。
- [ ] 1文要約に変化も狙いもない。

**3分口頭テスト**: 場面を口で説明するとき、動作を真似できるか。「傘を持つ」
「名簿を閉じる」が再現できるなら場面。「複雑な気持ちになった」だけなら要約。

### 18. 契約を approved にする
**必須は `scene_job` / `want` / `turn` の3項目。** 1つでも空なら approved にしない
(write-scene のゲートもこの3項目を見る)。その他の欄 (`dramatic_question` /
`obstacle` / `cost` 等) は場面の必要に応じて埋める。埋めた craft 欄を
`contracts/<E-S>.md` に記入し `status: approved` にする。`plan/tree.md` の
シーン状態も approved に。**ここまでが本文生成の前提**で、`write-scene` は
approved でない契約では書かない (試作だけなら `scratch/` を使ってよい)。

## 記入例 (一例であり、同じ題材やトーンに引っ張られないこと)

```yaml

dramatic_question: ミナは傘を忘れられるのか
want: ミナが自分の傘を今すぐ取り戻したい
obstacle: 係員が「まだ預かっていない」と受け取りを拒む
turn: 傘を受け取ると思ったら、忘れてから来いと言われる
cost: 傘を持ったまま雨へ戻る (濡れる・遅刻する)
entry: 「お預かりは、まだです」

button: 手元の傘が、少しだけ重い。
detonator: 名簿に、まだ忘れていないミナの名前が先に書いてある

```

## 出力・記録先

| 出力 | パス |
| --- | --- |
| craft 欄入り契約 | `contracts/<E-S>.md` |
| 計画状態の更新 | `plan/tree.md` |
| 設計の相談メモ (任意) | `proposals/p-XXXX.md` |

## アンチパターン

- **契約が本文のあらすじになる**: craft 欄は機能・問い・変化だけを書く。
- **want が抽象語**: 「成長したい」は動作にならない。
- **obstacle が天候・雰囲気**: ノーと言う主体がいない障害は緊張を作らない。
- **turn がない / 変化がない**: 何も変わらず、ただで解決する。削るか作り直す。
- **entry が説明・exit が総括**: 遅く入り、早く出る (CRAFT §1原則9)。
- **concrete_details が形容詞**: 「美しい」「古い」は具体物ではない。
- **subtext なし**: 全員が本音を言い、台詞が説明になる。
- **場面を2つ混ぜる**: turn が2つある契約は2場面に分ける。
- **全欄を埋めようとして手を止める**: 探索的な場面は他の欄を開けてよいが、
  **scene_job / want / turn の3項目は空にしない**。

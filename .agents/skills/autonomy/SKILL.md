# autonomy — 自律運転

自律運転は作者の明示許可でのみ開始する。auto は「承認を省く」だけであって
「検査を省く」ではない。**完走 ≠ 品質合格。**

## いつ使うか

- 作者が「任せる」「自律で進めて」と明示したとき。
- 停止した自律運転を、ファイル上の status / pending から再開するとき。

## 入力

- `work.md` の自律運転ポリシー (レベル・上限・停止条件) と `mode`。
- `plan/tree.md`、pending の `proposals/`、`polished` の状態。
- `dialogue.md` 末尾 (前回の停止理由)。

## 手順

1. レベル (draft|auto) と上限を確認する。
2. 状態を読み、次に進めるべき1作業を決める。
3. 作業を実行する (本文は `write-scene`、計画は `plan-work` の手順)。
4. `dialogue.md` に実施内容と自動承認を記録する。
5. 品質停車点 (話末・上限到着) で beta-read → polish → release-gate を通す。
6. 停止条件に触れたら止め、問題・直前の正常な作業・再開条件を報告する。

## 開始条件

- `work.md` の執筆ポリシーに自律運転ポリシーがある (レベル・上限・停止条件)
- レベルは2種:
  - **draft**: 草案・提案作成まで。正典確定・計画確定・承認が要る変更は
    すべて提案 (`proposals/`・`changesets/`) に留める
  - **auto**: 自分が起票した提案を**自己承認**して適用まで進める
    (auto_approved 印つき)。後述の「常に停止するもの」以外は作者を待たずに
    連鎖させてよい — 計画提案→承認→契約提案→承認→本文生成→検査まで進む

## 3つのパス (膨張パスは禁止)

字数・退屈への対処は必ず次のどれか。迷ったら削減パスを選ぶ。

- **場面化パス (許可)**: 字数が prose_floor に届かない・場面が薄い・要約体に
  なっているとき、既にある turn (転) と cost (代償) を具体・動作・台詞・
  五感で**演じ直す**。新しい設定・事件を発明しない。情報を足すのではなく、
  すでに決まっている変化を読者に見せる。
- **削減パス (許可・推奨)**: 前置き・説明過多・重複・AI特有の冗長な言い換え・
  読者が既に知っていることを削る。削減率 (10–20% 等) を機械的な目標にせず、
  `craft/voice.md` の「削らない味」や初見読者向けの最小限の補助線は残す。
  削りすぎて下限を割ったら、説明を戻すのではなく場面化で立ち上げ直す。
- **膨張パス (禁止)**: 字数を満たすための挿入・水増し・同義反復・形容詞の
  重ね・要約で話数や文字数を稼ぐ・意味のない場面の追加・「〜することに
  なる」での引き延ばし。発見したらその往復を失敗として扱い、削減パスに
  切り替える。

## auto レベルでも常に停止して作者に聞くもの

- L2 以上の変更セット (正典・人物・時間軸・伏線の変更)
- `[秘密]` の新規確定・開示方針の変更
- 作者の過去の明示決定の破棄・上書き
- `[意図的未確定]` 項目の確定
- force_override 全般 (常に作者専用の緊急経路)

これらに触れた時点でその往復は止め、何が必要かを報告する。

## auto_approved の記録

- 提案・契約ファイルに `auto_approved: true` と時刻を記す
- `dialogue.md` に往復ごとの自動承認一覧を追記する
- 自動承認したものはあとから作者が `.agents/skills/change-set` で
  取り消し・修正できる (git 管理があれば履歴も追える)

## 品質停車点 (auto レベル必須)

速度は品質に従属する。以下で必ず停車し、通過するまで先へ進まない:

1. **話ごとに停車** (short は全編で1回、または `work.md` で設定した間隔):
   `.agents/skills/beta-read/SKILL.md` の**外部化批評+興味スコアカード**を
   通す。同一コンテキストの自己採点は停車点として数えない。
2. **閾値超過** (既定: high 1件 or medium 3件) → 場面化パス/削減パスで
   興味 revise (最大2回) → なおダメなら自律停止し、作者に報告する。
3. **polish 必須**: 全話が `polished: true` になり `reviews/polish-*.md` に
   記録が残るまで、次工程 (release-gate / export) へ進まない。
4. **release-gate 必須**: 公開前に `python3 tools/release_gate.py` と
   `python3 tools/manuscript_lint.py` を通す。
5. **未合格のまま上限到達**: 実行上限に達しても interest / polish / release が
   未合格なら、**「未完了」と報告する**。「完走した」と書かない。何が未合格か
   (どの話のどの観点か) を添える。

## 1往復の進め方 (各往復 = 1作業単位)

往復ごとに以下の自律指示に従う (draft レベル):

> これは自律実行モードによる往復です。作者からの新しい指示ではありません。
> 現在の作品状態を確認し、計画・草案・提案のうち次に進めるべき作業を
> 1つ進めてください。正典の確定・作者の承認を要する変更は、確定せず
> 提案の形に留めてください。進めるべき作業がない、または作者の承認・
> 判断・返答が必要な場合は、理由を簡潔に述べて停止してください。

auto レベルの往復指示:

> これは自律実行モード (auto) による往復です。次に進めるべき作業を
> 1つ進めてください。自分で起票した提案・契約は自己承認して適用まで
> 進めて構いませんが、auto_approved 印と記録を残してください。
> 「常に停止するもの」に触れたらその往復で止め、理由を述べてください。
> 品質停車点では beta-read と polish を飛ばさないでください。

1. 状態を読む: `work.md` / `plan/tree.md` / pending proposals /
   `polished` の状態 / review_required の有無。
2. 次の1作業を決めて進める。
3. `dialogue.md` に「自律往復: 何をしたか・何を自動承認したか」を追記する。
4. 副作用ゼロの往復 (読んだだけ) は作者の判断待ちとみなして停止する。

## 停止条件 — どれか1つでも該当したら止める

- 未解決の重大矛盾がある
- 現在の計画が執筆前ゲート (Writing Contract、craft 欄含む) を満たさない
  (auto では契約案を起票→自己承認して満たせるが、契約に必要な決定を
  作者しか持たない場合は停止)
- 「常に停止するもの」に触れた
- review_required の範囲に作業が踏み込む
- 品質停車点での findings が閾値超過した
- 設定された実行上限 (往復数) に達した
- 進めるべき作業がない / 作者の判断・返答が必要
- 同じ作業の再試行が続く (異常なリトライ)
- 品質ゲート (interest / polish / release) が未合格のまま完走扱いに
  なりそうになった

停止時は「問題・直前の正常な作業・再開に必要なこと」を `dialogue.md` に
残し、作者に報告する。次の往復はそこから安全に再開できること。

## 出力・記録先

- `dialogue.md` に往復ごとの実施内容・自動承認一覧・停止理由
- `auto_approved` 印は提案・契約ファイルに
- 品質停車点の結果は `reviews/` (beta-*.md / polish-*.md)

## アンチパターン

- 膨張パスで字数を満たす (挿入・水増し・要約での引き延ばし)。
- 停車点で自己採点を外部評価の代わりにする。
- `polished: true` でない原稿を公開工程へ流す。
- 実行上限に達しただけで「完走」と報告する。
- 承認を省くことと検査を省くことを混同する。

# write-scene — シーン本文の生成

パイプライン: write → critique (整合性+興味) → revise (整合性1回+興味2回) → 確定。
**本文は要約ではなく場面である。** 整合性検査に通ることは出荷条件であって、
面白さの代わりにはならない。

## いつ使うか

- 承認済み契約のシーン本文を書くとき・書き直すとき。
- 退屈・要約体・説明過多を指摘された本文を興味 revise するとき。

## 手順

1. ゲートを通す → 2. 入力を組み立てる → 3. writer で起草 → 4. 決定的検査・
critic・自己興味監査 → 5. revise (整合性1回・興味2回まで) → 6. 確定。
各段の内容を以下に書く。

## ゲート (必須。ここを通らない本文生成は禁止)

1. `contracts/<scene>.md` が存在し **status: approved** であること。
2. `plan/tree.md` でそのシーンが approved であること。
3. 契約の craft 欄の必須項目 (**scene_job / dramatic_question / want /
   obstacle / turn / cost**) が空でないこと。空なら
   `.agents/skills/scene-craft/SKILL.md` に戻って設計する (書いてから埋めない)。
4. 契約の `base_revision` と `work.md` の `canon_revision` を比較し、
   以降に関連する正典変更があれば作者に確認してから進める。
5. 契約がない・未承認・不足 → 生成を保留し、契約提案
   (`proposals/` kind: writing_contract) か質問で対話に戻る。

## 入力

**関連する部分だけ読む** — ファイルは育つので全量を毎回読まない。
契約・participants・場所・depends_on に紐づく ID と言及検出で絞る。

- `contracts/<scene>.md` (契約全文。**craft 欄を最優先で読む**)
- `work.md` の「面白さの設計」、`craft/engine.md` (面白さの源泉・欲求・対立・代償・時計・意図的な逸脱)
- `craft/voice.md` (声のサンプル段落・**削らない味**・既定で避ける語彙・テンポ)
- `canon/facts.md` (関連行。[秘密] は全件確認)
- `entities.md` (登場要素 — POV 解決・関係・位置関係)
- `knowledge.md` + 契約の knowledge_notes → **視点人物が知っている事実の集合**
- `events.md` の前後の出来事 (時系列照合)
- `foreshadowing.md` (このシーンで張る/回収する伏線)
- 直前シーンの本文末尾 (接続の材料。文体のつなぎ目)
- 作者の書き直し指示 (再生成時)

## writer 役割プロンプト

> あなたは小説作品の「執筆担当」です。渡された Writing Contract に厳密に
> 従って本文を書いてください。禁止事項を破らず、必須イベントを含めてください。
> 正典メモと矛盾する設定を新たに作らないでください。
> 正典メモの先頭ラベル: [約束済み]=近い将来の約束。 [仮置き]/[未判断]/
> [意図的未確定]=未確定なので本文の確定事項に使わない。 [秘密]=読者にも
> 未登場人物にも知られたくない事実。ただし「視点人物が知っていること」に
> 挙がっている事実は、その視点の叙述として出してよい。
>
> **面白さの指示 (衛生・要約禁止は厳守。表現技法は `craft/voice.md` / `craft/engine.md` の宣言を優先):**
> - 要約するな。場面として演じよ。あらすじ・ビート見出し (「一」「二」)・
>   箇条書き・「〜することになる」の要約体は本文ではない。
> - 契約の turn (転) と cost (代償) を演じる (静かな余韻や日常の呼吸など
>   `craft/engine.md` に意図的な逸脱が宣言されている場合はその狙いを優先)。
> - 五感と固有の事物で書け。既定では感情を安易に名指しせず動作・台詞・具体物で
>   立ち上げる。ただし `craft/voice.md` の「削らない味」(過剰な一人称独白・
>   クセ・息抜き・生活感・ユーモア等) に宣言された表現は自主規制せず活かす。
> - 台詞には目的と人物の体温を持たせよ。全員に説明させたり、全員がキメ台詞ばかり
>   吐いて淡々とした舞台劇にしない。誰が言ったか分からない台詞を書くな。
> - 独自設定や強いメタファーを扱うときは、前提知識ゼロの読者が世界の物理ルールや
>   因果関係に置いてけぼりにならない最小限の補助線 (講義ではなく行動・手触り・
>   小さな実演) を置く。
> - 既定では entry は遅く、exit は早く。読者が次を読む理由 (残った問い・
>   気になる代償・余韻) を場面の終わりに残せ。ただし契約の end_state を越えるな。
> - 展開が予定調和・お使いになりそうなときは、`docs/CRAFT.md` §4 の打開策カタログ
>   (失敗と悪化・割り込み・判断ミス・敵役の筋の通った正義等) から作品に合うものを
>   自律的に選んでよい (必須ではない)。
> - 文字数は prose_floor を**下限**として満たす。届かないときは具体・動作・
>   台詞で場面を厚くする (場面化パス)。文を足して水増しするな
>   (膨張パス禁止)。voice_notes と prohibit_summary (true 固定) に従う。
>
> 本文と併せて以下も出してください:
> - canon_facts_new: 本文生成で新たに確定した正典メモ (あれば)
> - depends_on: 依拠した正典/計画/シーンの ID 一覧

本文の形式: 本文のみ。見出し・解説・メタ発言・箇条書きは書かない。
段落は空行で区切る。

## 検査 (critique 段)

### 決定的検査 (自分で確認)

- [ ] `forbidden` の各項目が本文に出ていない (文言一致・構成要素の全出現)
- [ ] `required_events` の各項目が本文で触れられている
- [ ] `[秘密]` の内容が出ていない — 視点人物が `knowledge.md`/契約で正当に
      知る事実は除く (早期開示チェック)
- [ ] `[仮置き]` を本文の確定事項として使っていない
- [ ] 台帳参照の混入がない — シーンID (`N-N` 形式)・「第N部」等の管理見出し・
      ファイル名・台帳ID (`f001` `p-0001` `cs-0001` 等)・「〜で読んだ」系の
      メタ参照は**自動失格**。読者は台帳を持たない
- [ ] 本文中の登場要素を `entities.md` の name+別名で照合し、言及一覧を記録。
      契約の participants と実登場が一致するか確認する
- [ ] 契約の `end_state` を越えていない (越えていれば low: 境界)
- [ ] 話単位の頻出表現・薄い副詞・定型句が蓄積していない (頻度lint)
- [ ] 作中時間・時刻が `events.md` や前シーンと矛盾しない
- [ ] 状態の巻き戻りがない (死亡・退場済み人物の行動、不在場所の人物、
      失った物品の所持、壊れた物の復元等)。dream/memory/hypothetical は対象外
- [ ] 現実依存の事実 (年号・職業動作・手続・専門知識) を未検証のまま確定
      記述にしていない — 疑わしければ notes に残し `.agents/skills/research` へ

### critic 役割プロンプト (意味判断が要る検査)

> あなたは小説作品の「検査担当」です。生成本文が Writing Contract に適合して
> いるか検査してください。必須イベントの欠落、禁止事項への抵触、POV逸脱、
> 正典メモとの矛盾を violations に列挙してください。
> [仮置き]/[未判断]/[意図的未確定] を確定事項として使っていたら違反 (high)。
> [秘密] の内容が出ていたら秘密の早期開示 (視点人物の正当な知識は除く)。
> さらに**興味の観点**で検査してください: この場面は要約体になっていないか /
> ビート見出し・箇条書きが混ざっていないか / 予定調和・淡々とした説明に落ちて
> いないか / 場面の前後で何かが変わっているか / 読者が次を読む理由が残るか /
> 初見読者が仕組みや因果に置いてけぼりにならないか。
> (`craft/voice.md` の「削らない味」や `craft/engine.md` の意図的な逸脱で
> 宣言された表現は違反とみなさない。)
> severity: high=必須イベント欠落・禁止違反・正典と明確な矛盾・要約体 /
> medium=契約の意図から外れる・明白な退屈 / low=些細な違和感。
> 確信を持てない場合は「問題なし」と断定せず notes に残してください。

### 自己興味監査 (必須)

critic の後に、自分の書いた本文を疑う目で行う。3つ以上の項目が落ちたら
興味 revise に回す。

- [ ] この場面を1文で要約したとき、変化と代償 (または `craft/engine.md` に宣言
      した狙い) があるか (先が読めるお使い進行になっていないか)
- [ ] ビート見出し・番号行・【】見出し・本文中の `#` 見出しがないか
- [ ] 「〜することになる」「〜のである」の要約体が連続していないか
- [ ] 感情の安易な名指しや薄い副詞が意図なく過剰でないか (`craft/voice.md` の
      「削らない味」で宣言した語り口・過剰さは除外)
- [ ] 五感・具体物が3つ以上あるか (契約の concrete_details と対応)
- [ ] 台詞が誰のものか、台詞だけ抜いて判別できるか (全員がキメ台詞で均質化していないか)
- [ ] 台帳ID・メタ発言・出典URL・管理見出しが混入していないか
- [ ] `python3 tools/manuscript_lint.py scenes/<id>.md` が **exit 0** (E 0件)。
      W は推敲対象として記録する (E があれば修正必須)

## revise 段

- 整合性 (決定的検査・critic の high) の違反 → 指摘一覧を渡して**1回**書き直す。
- 興味監査・興味検査の不合格 (要約体・退屈・予定調和・変化なし・説明過多)
  → **最大2回**まで興味 revise する。指摘は「どこが退屈か」「何が変わって
  いないか」「どこが予定調和か / 初見に伝わりにくいか」の形で渡す。
- 直し方は場面化 (具体・動作・台詞・五感で演じ直す、`docs/CRAFT.md` §4 の
  打開策カタログの任意活用) か削減 (ノイズ・説明過多・重複を削る)。
  **水増し (膨張パス) は禁止** — 字数不足や退屈を文字の追加で埋めない。
- 整合性1回 + 興味2回の上限を超えて直りきらなければ、findings を残して
  作者に報告する。ループを続けない。

## 確定

1. `scenes/<E>-<S>.md` に本文を保存。rev を +1、source: ai、contract/
   depends_on/mentions、**`polished: false`** を記入 (行末コメントを付けない —
   `release_gate.py` が行全体の一致で読む)。旧本文は
   `scenes/history/<E>-<S>/r<N>.md` へ退避 (git があれば任意)。
2. `canon_facts_new` を `canon/facts.md` に追記 (出所: `scene 1-2 本文`)。
   重複宣言は追加しない。
3. `plan/tree.md` のシーン状態を generated に更新。
4. `events.md` に出来事を記録する (1シーン1件、または「記録不要」の明示)。
5. 本文で導入したが正典未登録の世界観詳細を洗い、`canon_facts_new` に入れるか
   「正典化しない」かを1行ずつ決めて `dialogue.md` に残す。
6. `dialogue.md` に生成結果 (rev、整合性/興味の検査サマリ、書き直し回数) を
   追記し、作者に報告する。**「整合性 OK」だけで「面白い」と報告しない。**

## 出力・記録先

- `scenes/<E>-<S>.md` (本文 + ヘッダ)
- `canon/facts.md` / `events.md` / `plan/tree.md` / `dialogue.md`
- 興味の自己監査結果は `dialogue.md` に要約 (必要なら `reviews/` にも)

## アンチパターン

- 要約・あらすじ・ビート見出しを本文として出す。
- 契約の craft 欄が空のまま書き始める (設計せずに書く)。
- prose_floor (下限字数) を目標と誤解し、挿入・同義反復で水増しする。
- 感情を名指しして済ませる (「悲しかった」)。
- 全員が説明のために喋る (説明会話)。
- 整合性検査に通っただけで「面白い」と報告する。
- 検査を飛ばして確定する。

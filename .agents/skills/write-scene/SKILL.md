# write-scene — シーン本文の生成

パイプライン: write → critique → revise → 確定。

## ゲート (必須。ここを通らない本文生成は禁止)

1. `contracts/<scene>.md` が存在し **status: approved** であること。
2. `plan/tree.md` でそのシーンが approved であること。
3. 契約の `base_revision` と `work.md` の `canon_revision` を比較し、
   以降に関連する正典変更があれば作者に確認してから進める
   (契約作成時点と正典がずれていないかの競合確認)。
4. 契約がない・未承認・不足項目がある → 生成を保留し、契約の提案
   (`proposals/` kind: writing_contract) か質問で対話に戻る。

## 入力の組み立て

**関連する部分だけ読む** — ファイルは育つので全量を毎回読まない。
契約・participants・場所・depends_on に紐づく ID と言及検出で絞る。

- `contracts/<scene>.md` (契約全文)
- `canon/facts.md` (確度ラベルつき。契約・登場要素に関連する行を主に、
  [秘密] は全件確認)
- `entities.md` (登場する要素のエントリ — POV解決・関係・位置関係・
  言及検出に使う)
- `knowledge.md` + 契約の knowledge_notes → **視点人物が知っている
  事実の集合**を組み立てる
- `events.md` の前後に位置する出来事 (時系列照合用)
- `foreshadowing.md` (このシーンで張る/回収する伏線の確認)
- 直前シーンの `scenes/` 冒頭抜粋 (接続の材料)
- 作者の書き直し指示 (再生成時)
- `work.md` の憲章・ポリシー・構造化ファイル欄 (登録済みストアがあれば
  該当箇所を参照)

## writer 役割プロンプト

> あなたは小説作品の「執筆担当」です。渡された Writing Contract に厳密に
> 従って本文を書いてください。禁止事項を破ってはいけません。必須イベント
> はすべて含めてください。正典メモと矛盾する設定を新たに作らないで
> ください。
> 正典メモの先頭ラベル: [約束済み]=近い将来の計画として約束済み。
> [仮置き]/[未判断]/[意図的未確定]=未確定なので、本文の確定事項として
> 使ってはいけません。[秘密]=読者にも未登場人物にも知られたくない事実
> なので、本文には絶対に書かないでください。ただし「視点人物が知って
> いること」に挙がっている事実は、その視点の叙述として出して構いません。
> 検査で指摘された問題をすべて解消した版を書いてください (再生成時)。
>
> 本文と併せて以下も出してください:
> - canon_facts_new: 本文生成で新たに確定した正典メモ (あれば)
> - depends_on: この本文が依拠した正典/計画/シーンの ID 一覧 (依存宣言)

本文の形式: 本文のみ。見出し・解説・メタ発言・箇条書きは書かない。
段落は空行で区切る。

## 検査 (critique 段)

### 決定的検査 (自分で確認)

ドラフト本文に対して必ず確認する:

- [ ] `forbidden` の各項目が本文に出ていない (文言一致・構成要素の全出現)
- [ ] `required_events` の各項目が本文で触れられている
- [ ] `[秘密]` 正典の内容が本文に出ていない — ただし視点人物が
      `knowledge.md`/契約で正当に知る事実は除く (早期開示チェック)
- [ ] `[仮置き]` 正典を本文の確定事項として使っていない
- [ ] `[秘密]` 正典が契約の knowledge_notes に書かれていない
      (視点人物の知識宣言と秘密ポリシーの矛盾)
- [ ] 本文に台帳参照が混入していない — シーンID (`N-N` 形式)・
      `第N部` 等の管理見出し・ファイル名・「〜で読んだ/見た」系の
      メタ参照は**自動失格**。読者は台帳を持たない — 本文が台帳を
      参照したら世界が壊れる
- [ ] 本文中の登場要素を `entities.md` の name+別名で照合し、言及一覧を
      記録する (依存エッジ副経路)。同時に契約の participants と
      実登場が一致するか確認する (未登場の参加者・契約外の登場は要確認)
- [ ] 契約の `end_state` を本文末尾が越えていない (越えていれば
      low: 境界 として記録)
- [ ] 話単位の頻出表現が蓄積していない — 薄い副詞・定型句の直近の話内
      出現頻度を数え、突出していれば finding (頻度lint)
- [ ] 作中時間・時刻の経過が `events.md` や前シーンと矛盾しない
      (同日なのに日付が変わる、移動時間が不可能、等)
- [ ] 構造的に判定可能な違反がない — 死亡・退場済み人物が行動していない、
      不在の場所に人物がいる、失った・渡した物品を依然所持している、
      壊れた・消費されたものが復元している、等 (状態の巻き戻り全般)。
      **ただし scene_type が dream / memory / hypothetical 等の場面は
      実時間を進めないので対象外**
- [ ] 現実依存の事実 (年号・職業動作・手続・専門知識) で未検証のものを
      確定記述にしていない — 疑わしいものは notes に残し、必要なら
      `.agents/skills/research` に回す

### critic 役割プロンプト (意味判断が要る検査)

> あなたは小説作品の「検査担当」です。生成本文が Writing Contract に
> 適合しているか検査してください。必須イベントの欠落、禁止事項への抵触、
> POV逸脱、正典メモとの矛盾を violations に列挙してください。
> [仮置き]/[未判断]/[意図的未確定] は未確定です — 本文が未確定の正典を
> 確定事項として使っていたら違反です (high 相当)。[秘密] の正典の内容が
> 本文に出ていたら秘密の早期開示として違反です (視点人物の正当な知識は
> 除く)。
> severity: high=必須イベント欠落・禁止違反・正典と明確に矛盾 /
> medium=契約の意図から外れるが致命傷ではない / low=些細な違和感。
> 確信を持てない場合は「問題なし」と断定せず notes に残してください。

## revise 段

severity=high の violation が1つでもあれば、指摘一覧を writer に渡して
**1回だけ**書き直させる (書き直しループはしない — 1回で打ち止め)。
直りきらなければ findings を残して作者に報告する。

## 確定

1. `scenes/<E>-<S>.md` に本文を保存。ヘッダの rev を +1、source: ai、
   contract/depends_on/mentions を記入。旧本文は `scenes/history/<E>-<S>/r<N>.md` へ退避 (git があれば任意)。
2. `canon_facts_new` を `canon/facts.md` に追記 (出所: `scene 1-2 本文`)。
   重複する宣言は追加しない。
3. `plan/tree.md` のシーン状態を generated に更新。
4. `events.md` に出来事を記録する — 1シーン1件、または「記録不要」の
   明示。忘れると追跡が取れなくなるので確定時に必須。
5. 本文で導入されたが正典未登録の世界観詳細を洗い、`canon_facts_new`
   に入れるか「正典化しない」かを1行ずつ決めて `dialogue.md` に残す。
6. `dialogue.md` に生成結果 (rev、検査サマリ high/medium/low 件数、
   書き直しの有無) を追記し、作者に報告する。

(複数シーンを話単位でまとめて確定してもよい — ただし各シーンの検査は
必ず通す)

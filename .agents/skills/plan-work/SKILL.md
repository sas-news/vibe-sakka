# plan-work — 計画立案 (planner)

## 入力

- `work.md` (title/premise/genre/憲章/ポリシー)
- `plan/tree.md` (現状の骨格。空なら新規計画)
- `canon/facts.md` (確度ラベルつきのまま読む)
- `foreshadowing.md` (張設済みで未回収の伏線 — 回収を計画に組み込むか
  判断する)
- 作者からの計画指示 (焦点・範囲。あれば)

## planner 役割プロンプト

> あなたは小説作品の「計画担当」です。作品の前提・憲章・ポリシーと現状の
> 計画ツリーから、エピソードとその配下のシーン構成案を作ってください。
> 各シーンにはタイトルと目的 (purpose) を付けてください。
> 既存の計画ツリーがある場合は、それを壊さない追加分のみを提案して
> ください。未確定 ([仮置き]/[未判断]/[意図的未確定]) の正典を確定
> 事項として計画に組み込まないでください。

出力案の形:
```
第N話 <タイトル>
  - <シーンタイトル>: <目的>
```

## 手順

1. 入力を読み、計画案を作る。**計画は提案であって確定ではない**。
2. 案を `proposals/p-NNNN-plan-<slug>.md` (kind: plan) として書き、
   対話で作者に提示する。既存計画との関係 (追加/変更/再構成) を明記する。
3. 作者が承認したら `plan/tree.md` に適用する:
   - 新規話・シーンを追加 (状態 draft、シーンID `<E>-<S>` を振る)
   - 各話にアークの到達点・確度を注記
   - proposal の status を approved に更新
4. **先行範囲の確認** (標準値):
   - 現在生成する話・シーンの目的と状態変化は詳細に確定
   - 属するアーク/短編全体の到達点と因果骨格を確定
   - 次の2つの物語単位の主要ビートを [約束済み] に
   - 作品全体の結末は方式次第 (blueprint なら必須、rolling なら未確定可)
   - 不足があるまま本文生成に進まない — 対話に戻して決める
5. `dialogue.md` に計画決定を追記する。

## 注意

- 計画ツリーの変更自体も変更管理の対象。承認済み計画を壊す追加・順序
  変更・削除は `.agents/skills/change-set` で update_plan の変更セットにする。
- 章数を機械的に満たすことが目的ではない。「次の生成が後続の物語を
  壊す自由すぎる賭けになっていないこと」が基準。

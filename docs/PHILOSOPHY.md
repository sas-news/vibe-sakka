# PHILOSOPHY — なぜ「面白さ」を工程にするのか

## 1. 破綻しない退屈は、いちばん高くつく

整合性の検査に落ちない原稿を書くのは、AI にとって容易である。設定を覚え、
矛盾を避け、禁止事項を守り、必須イベントを漏らさない。だがそれは
**「読まれないが正しい文章」** を生む。読者は正しさに金を払わない。
読者は「次を知りたい」に時間を払う。

v1 は破綻しない退屈を量産した。12話の小説が 8,500 字のあらすじになり、
レビューは「禁止 OK / 出荷可」と記録した。これはモデルの失敗ではなく、
**成功条件の設定ミス**である。成功条件が「破綻しないこと」なら、
エージェントは破綻しないものを納品する。それ以上は誰も要求していない。

v2 の成功条件は「読者が次を読みたくなること」。整合性は、その成功条件を
守るための下支えに降ろす。

## 2. 面白さは才能ではなく、工程である

面白さは神秘化されがちだが、少なくとも次の4つは工学的に扱える:

1. **引き** — 読者に未解決の問いを持たせ続ける (hook / pull)。
2. **変化** — 場面ごとに状況・関係・認識を変える (turn / cost)。
3. **具体** — 抽象語ではなく五感と固有の事物で語る (specificity)。
4. **意外と納得** — 予想を裏切り、振り返ると伏線がある (detonator)。

どれも「書く前に設計する」「書いた後に検査する」「削って密度を上げる」で
改善できる。才能ではなく、設計・検査・改稿の反復である。
だから v2 は、帳簿の工程を減らしてでも、この4つに工程を割り当てる。

## 3. AI がやりがちな「退屈」は、パターンで捕まえられる

AI の退屈な文章には特徴がある:

- 設定の説明から始まる (世界観の講釈、人物紹介の羅列)。
- 主人公が受動的で、出来事が「降ってくる」。選択と代償がない。
- 感情を名指しする (「悲しかった」「嬉しかった」)。動作・具体物がない。
- 会話が情報交換になる (全員が説明のために喋る。齟齬も下心もない)。
- 比喩が抽象的な在庫 (「まるで夢のよう」「心が温かくなった」)。
- 同じ構文・同じ段落長・同じリズムが続く。
- オチの前にテーマを説明する。読者を信頼していない。
- 全員が丁寧で、対立が回避される。誰も本気で何かを欲しがらない。
- 章末が「そして、次の日も続いた」のような閉じ方で、問いを残さない。

これらは `docs/CRAFT.md` で症状と処方として整理され、
`write-scene` の自己興味監査と `tools/manuscript_lint.py` の警告
(W001 感情の名指し、W005 反復、W009 要約体) で検出される。
AI の退屈は、才能の問題ではなく、パターンの問題である。

## 4. なぜ外部読者が必要か

書いた本人は、自分が知っていることを読者が知らないことに気づけない。
後で回収する伏線を「分かるはず」と思い、退屈な章を「必要な布石」と
正当化する。これは人間の作家にも AI にも共通する認知の歪みである。

v2 は外部化を必須にする。正典も計画も知らない読者に原稿だけを渡し、
「どこで読むのをやめたくなったか」「次を読む理由は何か」を聞く。
サブエージェントでも、別セッションでも、外部 LLM でもよい。大事なのは
**作者と知識を共有しない読者**であることだ。

## 5. なぜ「ノイズを削り、味を残す」のか

文章の面白さは、足し算より引き算で上がることが多い。

- 説明過多を削ると、読者が自分で補い、能動的になる。
- 前置きを削ると、異物が先に来て、読者が身を乗り出す。
- AI特有の冗長な言い換えや重複を削ると、テンポと密度が上がる。

v1 は逆をやった。字数が足りないから挿入し、台詞が壊れ、それを修復した。
一方で、**一律の削減率 (10–20% 等) を機械的な目標にすると、生活感・ユーモア・
感情の揺れ・初見読者向けの最小限の補助線まで削ぎ落ち、クールで淡々とした
舞台劇に均質化しやすい**。

v2 の `polish` は、AI特有のノイズ (冗長な言い換え・説明過多・既知の反復) を
容赦なく削りつつ、`craft/voice.md` に定めた作品の温度・リズム・意図的な
過剰さは守る。削る目的は文字数を減らすことではなく、その作品固有の味を
立ち上げることにある。

## 6. なぜ帳簿を減らすのか

正典・時系列・伏線・知識の管理は、長編では不可欠である。だが短編では、
帳簿の同期コストが面白さを磨く時間を奪う。v1 はすべての作品に同じ規律を
適用し、エージェントを帳簿管理者にした。

v2 はモードを分ける:

- **short**: 面白さの設計・興味監査・推敲・公開ゲートだけを必須にする。
- **serial**: 帳簿を維持し、さらに面白さのゲートを全話に足す。

帳簿は必要になった時だけ。その分の注意力を、フック・場面・台詞・推敲に。

## 7. 規範は創造を縛らない (既定指針と厳格ゲートの分離)

v2 が機械的に厳格なゲートを掛けるのは、**衛生・工程・安全面** (ゴミ混入・
破損・要約体の出荷・未推敲防止) である。一方、冒頭3段落の型・感情名指し
回避・欲求と障害と転と代償といった表現面の規範は、**「迷ったときの強力な
デフォルト」** であってハードルールではない。

荒唐無稽な展開も、過剰な一人称の心情吐露も、コメディや日常系の脱力も、
静かな余韻や形式実験も、`craft/engine.md` や `craft/voice.md` (および
`work.md` の検査ポリシー) に狙いを宣言すれば意図的に外してよい。

規範の目的は、作家を「減点されない文芸の型」にはめることではなく、**作品ごとの
面白さを作る反復を支えること**である。ビート見出しを禁じるのは形式の自由を
奪うためではなく、要約体が出荷される事故を防ぐため。リンクを禁じるのは検閲
ではなく、読者の没入を守るため。削ることを勧めるのは、長さを否定するためでは
なく、ノイズを除いて作品の味を濃くするため。

面白さの最終判断は作者にある。エージェントの仕事は、その判断が
「破綻」と「退屈」に邪魔されないように、工程を回し続けることである。
